# Languages

Persian (`fa`, RTL) is the default; English (`en`, LTR) is available in all three apps. Translation catalogs and locale metadata live in `libs/i18n/src`. No extra runtime dependency is needed for the current small catalog.

URLs begin with a locale, for example `/fa` and `/en`. An unprefixed URL redirects to the saved locale, or Persian. The explicit URL takes precedence over the preference. Switching languages preserves the rest of the path, query and hash and saves a host-only preference cookie for one year. Switching performs a navigation so Next.js HTML, metadata, text and Radix direction agree on the server and client. Cookies are shared across localhost ports, but not across separate production subdomains.

To add a language:

1. Add a catalog in `libs/i18n/src/messages`, conforming to `Messages` (missing keys are TypeScript errors).
2. Register its catalog, native label and direction in `locales` in `libs/i18n/src/index.ts`.
3. The locale union, URL validation and language picker derive from that registry automatically.
4. Extend browser tests for the new locale. Add future UI strings to every catalog; keep API machine codes untranslated and translate their user-facing presentation.

Use `Intl.NumberFormat` and `Intl.DateTimeFormat` with the active locale when adding amounts and dates. Currency and business timezone remain separate product decisions. Product/catalog content translations are outside this foundation.

# TypeScript

`baseUrl` is removed. All path mappings in `tsconfig.base.json` are relative to that configuration file (`./libs/...`). No `ignoreDeprecations` suppression is used. The API uses NodeNext module resolution. `.vscode/settings.json` points the editor to the installed workspace TypeScript. If an old diagnostic remains, select **TypeScript: Select TypeScript Version → Use Workspace Version**, then **TypeScript: Restart TS Server**.
